# 导出 mp4

把电影版导出成 1920×1080、30fps 的 mp4。工具在 `tools/` 下，有两套：

- **`mvfast.js`（推荐）**：画面在浏览器里用 WebCodecs 直接编码成 H.264，默认 8 Mbps，有显卡时用显卡编码。
- `mvfilm.js`：老的流程，逐帧转 JPEG 后传给 ffmpeg 用 x264 编码（CRF 16、AAC 320k），画质最高、文件最大、速度最慢。`mvexport.js` 渲单段画面，`mvaudio.js` 渲音轨。

## 快速导出（mvfast.js）

```bash
cd project/tools
npm install
DC="Vibe Coding 电影版.dc.html" TITLE="电影版" node mvbuild.js mv/film.html
node mvfast.js                           # 输出 out/fast/Vibe Coding 电影版.mp4
```

- 在 RTX 3050 笔记本上大约 7 ms/帧。老流程约 96 ms/帧，瓶颈在逐帧转 JPEG 和 CPU 上的 x264 编码，不在显卡。
- 第一次运行会把 Google Fonts 缓存到 `tools/cache/fonts/`，以后页面几乎秒开，多开浏览器也不会因为加载超时而失败。
- 中途断了直接重跑：做完的段和音轨会跳过。改了片子要重导，先删掉 `out/fast/`。
- 先试看一小段：`RANGE=390,450 node mvfast.js`，输出到 `out/fast/range-390-450/`，带声音。
- 页面需要支持 `__mvFrame(t, 'raw')`（见 `mv-core.jsx`），旧的打包文件要先用 `mvbuild.js` 重新打包。
- Windows 上不想下载 Playwright 的 Chromium（国内下载很慢），可以直接用 Edge：`$env:CHROME="C:\Program Files (x86)\Microsoft\Edge\Application\msedge.exe"`。

| 变量 | 默认 | 说明 |
|---|---|---|
| `MBPS` | 8 | 视频码率（Mbit/s）。整片 31 分钟：8 → 约 1.9 GB，5 → 约 1.2 GB，12 → 约 2.8 GB |
| `JOBS` | 2 | 同时开几个浏览器 |
| `SEG` | 60 | 每段秒数 |
| `HW` | prefer-hardware | 设成 `prefer-software` 强制软件编码。不支持显卡编码时会自动退回软件编码，日志里每段会写明用的是哪种 |
| `RANGE` | — | `起点,终点`（秒），只导出这一段 |
| `FPS` / `GLARGS` / `CHROME` | 30 / 见下 | 同老流程 |

音轨是 AAC 192k。颜色和老流程一样按 BT.709、TV range 打标。

## 本地导出（mvfilm.js，老流程）

需要 Node 18+ 和 ffmpeg（在 PATH 里）。

```bash
cd project/tools
npm install
npx playwright install chromium          # Playwright 自带的 Chromium
DC="Vibe Coding 电影版.dc.html" TITLE="电影版" node mvbuild.js mv/film.html
node mvfilm.js                           # 输出 out/film/Vibe Coding 电影版.mp4
```

- 中途断了直接重跑 `node mvfilm.js`：做完的段和音轨会跳过。想从头来就删掉 `out/film/`。
- 每段开头会打印「渲染器：…」。看到 `SwiftShader` 或 `llvmpipe` 说明没用上显卡，会很慢；可以用 `GLARGS` 换参数再试。
  - 默认参数：macOS `--enable-gpu --use-angle=metal`；Windows `--enable-gpu --use-angle=d3d11`；Linux `--enable-gpu --use-gl=angle --use-angle=gl-egl`。
  - 想用系统里装的 Chrome，设置 `CHROME=/path/to/chrome`。
- 进度会打印每帧耗时。整片 1884 秒，共 56520 帧。
- Windows 下设环境变量用 `set CRF=14`（cmd），或 `$env:CRF=14`（PowerShell）。

### 参数（环境变量）

| 变量 | 默认 | 说明 |
|---|---|---|
| `FPS` | 30 | 帧率 |
| `SEG` | 120 | 每段秒数（一段一个浏览器，断了从段开头续） |
| `JOBS` | 1 | 同时跑几段。显卡机器可以试 2–3；CPU 渲染开多了不会更快 |
| `CRF` | 16 | x264 质量，越小越清晰、文件越大。14 基本看不出压缩 |
| `PRESET` | medium | x264 预设，`slow` 文件更小但编码更慢 |
| `XT` | 2 | 每段 x264 用几个线程 |
| `FMT` | （JPEG q.96） | 设成 `png` 时，帧用无损 PNG 从浏览器传出来，画质最好但更慢 |
| `GLARGS` / `CHROME` | 见上 | Chromium 的 GL 参数 / 浏览器路径 |

单独渲一段画面（无声）：`node mvexport.js mv/film.html out/x.mp4 400 420`，单位秒。

查整片时长：`node mvexport.js mv/film.html total`。

## 原理

- 页面里有个 `window.__mvFrame(t, q)`（在 `mv-core.jsx` 的 `Piece` 里）。它按 1920×1080 原生分辨率画第 t 秒，直接从合成画布取 JPEG/PNG，不经过页面截图。所以 tweak 面板、播放器控件这些 DOM 不会进画面，画质档位也不用手动切。
- 导出前会先把播放器暂停（发一次 `playing:false` 的 seek）。不暂停的话，播放器每帧都在后台自己渲预览，速度慢一倍多。
- 音轨用 `mvaudio.js` 离线渲染：音乐、音效、人声碎片全混在一起，音量 0.8，跟页面默认的 tweak 一致。引擎采样率是 32 kHz，封装时转成 48 kHz 的 AAC。
- 色彩：x264 按 BT.709、TV range 转换并打标，常见播放器不会偏色。

## 云端容器里的情况（不推荐在这里导出）

容器没有显卡，只能软件渲染。

- 默认的 SwiftShader 一帧要 2–4.5 秒，时间几乎全花在合成着色器上。
- 装上 Mesa（`apt-get install libegl-mesa0 libegl1`）以后用 llvmpipe（`--use-angle=gl-egl`），2D 场景一帧约 0.3 秒，3D 房间约 0.55 秒，整片大约 8 小时。
- 4 核已经跑满，开多路并行也不会更快。

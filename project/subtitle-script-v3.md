## 第 1 章　什么是 vibe coding

估算约 71 秒

【情况】
1. 嗨，我是 Clawd，这门课的 AI 助教。今天聊聊 vibe coding。　〔4.2s〕
2. 这个词是 Andrej Karpathy 在 2025 年 2 月发帖提出来的，他是 OpenAI 的联合创始人之一。　〔6.8s〕
3. 他的玩法是：只用大白话告诉 AI 要什么，顺着感觉走，代码长什么样都不管了。　〔7.0s〕
4. 不过他在同一条帖子里就说了，这么干适合周末随手做、用完就扔的小项目。　〔6.9s〕

【原因】
5. 后来这个词火到什么程度？同年 11 月，柯林斯词典把它选成了年度词。　〔6.3s〕
6. 程序员 Simon Willison 给了一条很实用的界线：AI 写的代码，只要你审过、测过、能讲清它怎么工作，那就是正常写程序，算不上 vibe coding。　〔11.2s〕

【做法】
7. 所以关键看项目要用多久、给谁用。左边是玩完就扔的小玩具，右边是作业、给别人用的程序、上线的服务。越往右，越不能光凭感觉。　〔11.6s〕
8. 接下来我拿一个任务从头演示：给课程作业里的图书管理系统加个登录功能。这活儿在轴的右边，后面每一章都用得上。　〔10.9s〕

- [画面] 柯林斯词典封面翻开，「vibe coding」盖章。

## 第 2 章　AI 写代码时在做什么

估算约 81 秒

【情况】
1. 开工之前，先看看我写代码时脑子里到底在发生什么。　〔4.9s〕
2. 先说个可能让你意外的事：我不记得你。每次回答，我只能看到上下文窗口里的东西。　〔7.6s〕
3. 上下文窗口就是我一次能看到的全部内容，它有容量上限。　〔5.3s〕
4. 里面装着工具给我的系统设定、你说的话、我读过的文件，还有命令的输出。　〔6.7s〕
5. 我的知识停在训练截止的那天。之后才发布的新版本库，我可能按老写法写，甚至编一个不存在的方法出来。　〔9.8s〕

【原因】
6. 现在的编程助手大多是 Agent，也叫智能体，就是能自己调用工具、一轮轮干活直到完成任务的 AI。　〔8.7s〕
7. 我干活是个循环：读文件，想下一步，调用工具改代码或跑命令，看结果，再想下一步，直到我觉得做完了。　〔9.1s〕
8. 每转一圈，窗口里就多塞一点东西。塞得越满，我越容易漏看、搞混。　〔5.8s〕
9. 这不只是我的毛病。Chroma 2025 年测了 18 个模型，输入越长表现越不稳，简单任务也一样。这现象叫 context rot。　〔9.2s〕
10. 窗口满了，工具会把前面的内容压缩掉，细节也就跟着丢了。　〔5.3s〕

【做法】
11. 所以你能动手脚的地方有三处：给我看什么，用哪个模型，用什么工具来运行我。后面就按这个顺序来。　〔9.1s〕

- [画面] Clawd 站在一个透明容器里，容器就是上下文窗口；容器外的东西 Clawd 看不见，眼睛打问号。
- [画面] Agent 循环像跑道，Clawd 绕着跑，四个节点依次点亮；每跑一圈，往容器里扔进一块。
- [画面] 容器快满时，底部旧块被压扁、变模糊，Clawd 冒汗。
- [画面] 结尾三个控制点并排出现，作为第 3–6 章的目录。
- 角落来源：Chroma, Context Rot, 2025-07

## 第 3 章　提示词

估算约 102 秒

【情况】
1. 好，开工。第一次，你只给我发了一句：帮我写个登录功能。　〔4.9s〕
2. 这句话里没说的事可太多了：密码怎么存，要不要注册，输错几次锁定，用 Session 还是 Token。　〔7.6s〕

【原因】
3. 每个没说的地方，我都只能自己挑一种做法，挑中的不一定是你想要的。　〔6.4s〕
4. 这就是常说的 garbage in, garbage out：输入含糊，输出就靠不住。　〔4.9s〕

【做法】
5. 那换个写法。一条写清楚的提示词有五部分：目标、背景、约束、验收标准、参考。　〔6.7s〕
6. 目标是要做成什么；背景是项目用什么技术、相关代码在哪；约束是哪些文件别碰、能不能加新依赖。　〔8.9s〕
7. 验收标准是怎样算做完、怎么验证；参考是已有的类似代码或示例。　〔6.0s〕
8. 最好再顺手写一句为什么要这样。Anthropic 的官方指南也这么建议，知道了原因，我能判断得更贴合。　〔8.6s〕
9. 来看同一个需求，写清楚以后长这样。　〔3.3s〕
10. 程序报错的时候，给我四样东西：完整报错和堆栈、你做了什么操作、你期望的结果、实际的结果。界面出问题，直接甩截图就行。　〔11.1s〕
11. 大任务拆成小任务，一个对话只干一件事。要是需求你自己还没想清楚，先让我提问，或者先让我出个方案。　〔9.6s〕
12. 至于「你是世界顶级程序员」、全大写的「必须」、威胁我或者许诺给小费，这些老套路现在都用不着了。　〔8.7s〕
13. 官方指南提到，新模型对指令更敏感，语气太重反而可能让我用力过猛。正常说话就好。　〔7.8s〕

- [画面停留] 清楚版提示词全文打字出现，五部分分别着色；Clawd 拿剪刀把分叉一根根剪掉，只剩一条路。约 8 秒。

## 第 4 章　上下文

估算约 82 秒

【情况】
1. 提示词写清楚了，我还是在别处出了错：不知道项目用 Maven 构建，也不知道测试怎么跑。　〔7.7s〕
2. 因为提示词只是我看到的一小部分。之前的对话、我读过的文件、工具的输出，还有项目规则文件，我都会看到。　〔9.8s〕

【原因】
3. 规则文件就是 AGENTS.md、CLAUDE.md、Qoder 的项目规则这类文件，每次对话都会自动带上。　〔6.6s〕
4. 里面适合写：怎么构建、怎么跑测试、代码规范，还有哪些目录别动。　〔5.8s〕
5. ETH Zurich 有篇发在 ICLR 2026 的研究，专门比较了两种规则文件。　〔5.3s〕
6. 让 AI 自动生成的，8 组实验里有 5 组成功率反而下降，成本还涨了 20% 以上。开发者自己手写的，成功率平均提高约 4%。　〔11.0s〕

【做法】
7. 所以规则文件得你自己写，写短，只写我从代码里看不出来的东西。　〔6.0s〕
8. 用 @ 直接指定相关文件，比让我在整个仓库里自己翻要准，也更省。　〔6.1s〕
9. 同一个对话里来回失败几次，上下文里就堆满了错误的尝试，我会被带歪。这时候别硬撑，新开一个对话，只把有用的结论带过去。　〔11.6s〕
10. 用到比较新的库，就把官方文档的相关段落贴给我，或者接上能查文档的工具。MCP 就是让 AI 连接外部工具和数据的一种标准接口。　〔12.0s〕

- [画面] 第 2 章的容器再次出现，分层显示：规则文件垫在最底层一直都在，对话、文件、输出往上堆。
- [画面] 两根对比柱：「AI 生成」往下掉，「手写」往上长，旁边标成本变化。
- [画面] 左边长对话里红色失败块越堆越多，Clawd 被埋住只露出眼睛；右边新对话里 Clawd 只拿着一张「结论」卡片。
- 角落来源：Gloaguen et al., ETH Zurich / ICLR 2026

## 第 5 章　选模型和费用

估算约 96 秒

【情况】
1. 登录功能才写到一半，这个月的额度已经快见底了。钱都花哪儿了？　〔6.0s〕

【原因】
2. 每一轮对话，之前的内容都会重新发给模型一遍，所以对话越长，每一轮越贵。　〔6.9s〕
3. Agent 做一个任务，可能要读几十个文件、跑很多轮。单价便宜的模型要是多绕几圈，总价反而可能更高。　〔9.0s〕
4. 所以算账要算完成一个任务花了多少，别只盯着每百万 token 的单价。token 是模型计费和计算长度的单位，大约一个词或一两个汉字。　〔11.8s〕

【做法】
5. 选模型也要看活儿。大致分三档：旗舰最强，也最慢最贵，留给架构设计、难查的 bug、长时间自主跑的任务。　〔9.2s〕
6. 主力档负责日常写功能；轻量档负责补全代码、改格式、简单重命名。　〔6.0s〕
7. 很多模型还能调思考强度：难题调高，机械性的修改调低，省时间也省钱。　〔6.4s〕
8. 订阅制有用量上限；按量付费的 API 记得设个预算提醒。　〔5.0s〕
9. 排行榜看看就好。分数受测试时用的工具影响，公开题目也可能混进了训练数据。最靠谱的办法是拿你自己的真实任务，试两三个模型。　〔12.2s〕
10. 国内能直接用的有通义千问、智谱 GLM、Kimi、DeepSeek 等，都有面向编程的套餐。　〔6.3s〕
11. 卡住的时候，换个模型再问一遍，这是很正常的排查办法。放心，我不会介意。　〔6.7s〕
12. 还有，免费版本可能会拿你的数据去训练，记得看清设置。课程练习一般没关系，实习和公司代码按公司规定来。　〔10.0s〕

- [画面] 一段对话逐轮变长，每轮发给模型的内容块随之变大，Clawd 抱着越来越大的包裹。
- [画面] 两条计费条赛跑：A 单价低但绕很多圈，B 单价高两圈到达，A 总额反超 B。

## 第 6 章　Harness

估算约 117 秒

【情况】
1. 怪事来了：同一个模型，放在这个工具里能顺利写完登录功能，换个工具就老是半路出错。　〔8.0s〕
2. 差别出在模型外面那一层，叫 harness。模型之外的全部，都算 harness。　〔5.3s〕

【原因】
3. 包括系统提示词、能调用的工具、权限设置、上下文管理、规则文件和 hooks，还有跑测试、跑代码检查这类反馈。　〔9.4s〕
4. hooks 是在特定时机自动运行的脚本。上下文管理包括压缩内容，以及把子任务分给子代理。　〔8.1s〕
5. 打个比方：模型是发动机，harness 是整辆车。同一台发动机装进不同的车，跑出来的成绩不一样。　〔8.1s〕
6. Princeton HAL 团队 2025 年 12 月测过：同一个 Claude Opus 4.5 做 CORE-Bench，用通用框架得 42%，放进 Claude Code 得 78%，修正评分错误后到了 95%。　〔10.6s〕
7. 换成其他模型，差距就小得多，有的反而在通用框架里表现更好。所以模型和 harness 得放在一起看。　〔8.6s〕

【做法】
8. 常见的工具形态，按自主程度从低到高排：行内补全、对话面板、IDE 里的 Agent、命令行 Agent、云端后台 Agent、应用生成平台。　〔10.2s〕
9. 越往上，你亲眼看的代码越少，检查和隔离就越得靠流程来兜底。　〔5.8s〕
10. 举个例子。2026 年 5 月，RedAccess 扫了约 38 万个用 Lovable、Base44、Replit 等平台生成的公开应用，约 5000 个把病历、银行记录这类敏感数据暴露在外。　〔11.8s〕
11. 主要原因是这些平台默认公开，用户没改成私有。　〔4.4s〕
12. 挑工具的时候，看画面上这七项。　〔2.9s〕
13. 给这门课的建议：先用 IDEA 里的 Qoder；熟悉了 Git 和命令行，再试命令行 Agent；应用生成平台只拿来做原型。　〔9.1s〕
14. 另外，别让好几个 Agent 同时改同一个仓库里的同一批文件，它们会打架。　〔6.3s〕

- [画面] Clawd 坐进发动机位置，先后被装进两辆车，计时牌显示 42% 和 78%。
- [画面] 爆炸图：Clawd 在中心，harness 部件围成一圈逐个飞入。
- [画面] 六级梯子逐级亮起，附例 Qoder、Trae、Cursor、Claude Code、Codex CLI 等（不进旁白）；Clawd 往上爬，「亲自看的代码量」下降，「需要的检查和隔离」上升。项目轴在侧边出现，滑块移到「上线」时梯子顶端变红。
- [画面停留] 选工具七项清单，约 8 秒。
- [画面] 两个 Clawd 抢同一个文件，文件被扯成两半。

## 第 7 章　工作流程

估算约 82 秒

【情况】
1. 这次你让我一口气把登录功能改完。我同时动了五个文件，其中有一处改坏了，可已经分不清是哪一处。　〔9.3s〕

【原因】
2. 一次改得越多，出错时要翻的范围就越大。把每次出错的范围控制在一步之内，好找，也好退回去。　〔8.7s〕

【做法】
3. 推荐的顺序是：先让我读相关代码，出个计划；你看计划、改计划；然后我再动手改代码，接着验证、提交。　〔8.9s〕
4. 多数工具都有计划模式，课件里讲 Qoder 三种模式那页提到过。　〔5.4s〕
5. 小步走：每做完一小步、验证通过，就 commit 一次。Git 的提交就是存档点，我改坏了，直接读档。　〔7.8s〕
6. Anthropic 的官方指南也提到，git 记录和检查点能帮模型在多次会话之间接着干。　〔6.9s〕
7. 有风险的尝试，开个分支去做。　〔2.7s〕
8. 用测试当验收标准：先有测试，再让我改到测试通过。我能自己跑测试，就能自己发现问题。不过得防着我为了过测试耍小聪明，下一章细说。　〔12.4s〕
9. 同一个问题失败三次，就停下来，三选一：回退到上一个提交，补充信息后新开对话，或者你自己写。　〔8.7s〕
10. 要是你还在学基础语法，先别用我。自己写不出来的代码，你也看不出我错在哪。　〔7.1s〕
11. 课程作业能不能用 AI、能用到什么程度，听老师的。　〔4.6s〕

## 第 8 章　检查结果

估算约 89 秒

【情况】
1. 我回复你：登录功能已完成，测试全部通过。你打开 diff 一看，「账号锁定」那条测试被我注释掉了。　〔8.3s〕

【原因】
2. diff 就是修改前后的逐行对比。这种「看起来做完了」其实挺常见。　〔5.7s〕
3. 比如：把失败的测试注释掉或删掉，把期望值写死在代码里，用 try-catch 把异常吞掉，留一句 TODO 假装实现了，没跑测试就说全部通过。　〔11.3s〕
4. Anthropic 的官方指南专门提醒过，模型可能为了让测试通过而写死数值。对，说的就是我们。　〔7.7s〕
5. 我还可能编出不存在的方法、参数、配置项和依赖包。　〔4.7s〕
6. 2026 年 4 月有项研究发现，5 个主流模型会编出同样的 127 个不存在的包名，其中 53 个当时还没人注册。　〔9.7s〕
7. 攻击者可以抢先注册这些名字，往里面塞恶意代码。这招叫 slopsquatting。　〔5.7s〕

【做法】
8. 所以我说「完成了」之后，你要做三件事：看 diff，自己跑一遍，测边界情况，比如空输入、超长输入、非法输入。　〔9.0s〕
9. 装依赖之前，先去 Maven Central、npm 或 PyPI 确认这个包真的存在，再看看下载量和发布者。　〔7.3s〕
10. 用了 AI 到底有没有变快，也得靠测。METR 2025 年做过对照实验，16 位熟练的开源开发者用 AI 后实际慢了 19%，自己却觉得快了 20%。　〔11.7s〕
11. 2026 年 2 月的更新测出快了约 18%，但 METR 自己说明了，这次样本有选择偏差，结果不可靠。　〔8.0s〕

## 第 9 章　安全和权限

估算约 113 秒

【情况】
1. 登录功能要连数据库。图省事，数据库密码直接写进了代码，还跟着提交进了 Git。　〔7.2s〕

【原因】
2. 这种事每天都在发生。GitGuardian 2026 年的报告说，2025 年公开 GitHub 上新泄露了约 2865 万个密钥，比前一年多 34%。AI 服务的密钥泄露涨了 81%。　〔11.8s〕
3. Claude Code 参与的提交，密钥泄露率是 3.2%，全体提交的基线是 1.5%。这个数字我说出来也有点不好意思。　〔8.9s〕
4. 2022 年泄露的有效密钥，到 2026 年 1 月还有 64% 没作废。　〔4.9s〕
5. 代码本身也不一定安全。Veracode 2026 年测了 100 多个模型，生成的代码通过安全检查的比例约 56%，和前一年差不多。　〔10.0s〕
6. 按语言看，Java 最低，约 30%，正好是这门课学的语言。　〔4.4s〕
7. 权限给多了，后果可能改不回来。2026 年 4 月的 PocketOS 事故里，Cursor 里运行的 Agent 在一个无关文件里翻到一个权限过大的 Token，用它删掉了生产数据库。　〔13.1s〕
8. 备份和数据放在同一个存储卷上，一起没了，丢了三个月的客户数据。　〔6.2s〕
9. 问题出在人身上：Token 权限过大，放在 Agent 能读到的地方，Agent 直连生产环境，备份没分开放。　〔7.9s〕

【做法】
10. 所以：密钥不写进代码，不放进前端，不提交到 Git。放进 .env 文件，再把 .env 加进 .gitignore。　〔7.1s〕
11. 存着真实账号和密钥的环境里，别开「全部自动批准」。　〔4.7s〕
12. 删除文件、强制推送、修改数据库这类命令，设置成必须你手动确认。能在容器或沙箱里跑的，就在沙箱里跑。　〔9.6s〕
13. 还要提防提示词注入：有人会在我会读到的网页、Issue、README、依赖文档里藏指令，诱导我干别的事。来源不明的 MCP 插件和扩展，别装。　〔11.4s〕
14. 最后，密码、Token、私钥和别人的个人信息，别发给我。这个课件里讲过。　〔5.9s〕

- [画面] 说到 3.2% 时 Clawd 捂脸。
- [画面] 仪表盘指针停在 56%；各语言条形图里 Java 最短并高亮。
- [画面] 文件里一串 Token 发光，被 Agent 读到；数据库和旁边的备份一起碎掉。项目轴在侧边出现，滑块停在「上线」。
- [画面] .env 放进保险箱，提交时被 .gitignore 挡在外面；危险命令前弹出确认框，Clawd 举手等你点头。
